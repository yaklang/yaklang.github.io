# Memfit AI 录屏剧本

以下四支视频分别介绍 Memfit AI 的任务执行、知识库、长期记忆和能力组合。每支可以独立发布，也可以串联为合集。

## 视频 1：一句话生成可审阅的分析报告

**片名**：`从目标到交付：Memfit AI 生成分析报告`

**时长**：75 ~ 90 秒

**演示重点**：目标规划、文件读取、工具调用、人工确认与文件交付。

### 演示前准备

1. 新建空白目录 `memfit-order-demo/`。
2. 放入 `brief.md`：

```markdown
# 异常订单分析要求

- 识别金额、退款率或登录地区明显异常的订单。
- 每条判断必须引用订单号和原始字段。
- 结论按高、中、低风险分组。
- 保留原始数据，仅生成 output/analysis.md。
```

3. 放入 `orders.csv`：

```csv
order_id,user,amount,refund_count,login_region
O-1001,alice,199,0,Shanghai
O-1002,bob,12999,4,Unknown
O-1003,carol,299,0,Beijing
O-1004,dave,8999,3,Unknown
```

4. 在设置中启用文件操作，并将审查方式设为「人工确认」。

### 分镜与旁白

1. **0 ~ 8 秒｜加载工作上下文**
   - 画面：Memfit AI 首页，拖入 `memfit-order-demo/` 目录；右侧文件资源出现。
   - 旁白：「文件、任务约束与执行过程位于同一工作空间。」

2. **8 ~ 20 秒｜提交目标与执行约束**
   - 输入：

```text
读取 @brief.md 和 @orders.csv，分析异常订单并生成 `output/analysis.md`。
先给出计划；任何写文件操作都必须等我确认。保持原始文件不变。
```

   - 画面：Agent 生成计划卡片，包含「读取要求 → 校验数据 → 识别异常 → 生成报告」。
   - 旁白：「Agent 先生成计划，再按照任务依赖执行。」

3. **20 ~ 38 秒｜任务和证据一起推进**
   - 画面：确认计划；任务树开始执行。文件读取、数据检查和异常归类依次出现，展示工具参数与引用的订单行。
   - 旁白：「时间线记录工具调用、资源输入和中间结果。」

4. **38 ~ 53 秒｜写入前请求人工确认**
   - 画面：创建 `output/analysis.md` 前弹出审查卡片；展开参数，确认目标路径后点击同意。
   - 旁白：「写入前展示目标路径与操作参数，由用户确认。」

5. **53 ~ 72 秒｜交付物落地**
   - 画面：Artifact 卡片出现，打开 `analysis.md`；报告按风险分组，引用 `O-1002`、`O-1004` 及对应字段。
   - 旁白：「结果保存为可以继续评审和提交的文件。」

6. **72 ~ 90 秒｜回看完整链路**
   - 画面：回拉时间线，计划、任务、工具审查、Artifact 串成一条链。
   - 字幕：「目标 → 计划 → 工具 → 审查 → 交付物」

### 验收标准

- 出现一次计划确认和一次写文件确认。
- 最终文件路径为 `output/analysis.md`，原始文件修改时间保持不变。
- 报告中的每项判断回指 CSV 原始字段。

## 视频 2：把散落资料变成可追溯的知识网络

**片名**：`从资料到知识网络：构建可查询知识库`

**时长**：75 ~ 90 秒

**演示重点**：知识、向量、实体与关系联合索引；Agent 基于已挂载知识库生成可追溯回答。

### 演示前准备

- `product-overview.md`：写明 Demo 产品的模块、版本与负责人。
- `faq.txt`：写 5 条仅在演示资料中存在的售后规则。
- `incidents.csv`：写 6 条虚构故障，包含日期、模块、原因和解决方案。
- 植入一个可验证的跨文件问题：`Atlas Sync` 模块负责人是「林澈」，最近一次故障原因是「旧版签名缓存未失效」。

### 分镜与旁白

1. **0 ~ 10 秒｜资料散落**
   - 画面：Finder 中依次选中三份资料，切到 Memfit AI 知识库首页。
   - 旁白：「知识索引将分散资料转换为可检索、可关联的信息。」

2. **10 ~ 27 秒｜创建增强索引**
   - 画面：新建知识库 `Atlas Demo`，拖入三个文件，选择增强知识图谱索引并开始构建。
   - 旁白：「增强模式同时整理知识、向量、实体和关系。」

3. **27 ~ 45 秒｜查看关系图**
   - 画面：依次切换知识、向量、实体和关系图；点击 `Atlas Sync`，高亮负责人、故障和解决方案节点。
   - 旁白：「实体关系图显示跨文档连接，并可回到具体知识条目。」

4. **45 ~ 65 秒｜把知识库交给 Agent**
   - 输入：

```text
只根据 @Atlas Demo 回答：Atlas Sync 由谁负责？最近一次故障的根因和解决办法是什么？
如果资料没有说明，请明确回答“资料不足”，不要用常识补全。
```

   - 画面：回答列出负责人、根因、解决方案，并展开引用的知识条目。
   - 旁白：「知识库作为结构化上下文进入任务，回答可以核对来源。」

5. **65 ~ 80 秒｜导出知识资产**
   - 画面：打开潜在问题列表，随后导出 `Atlas-Demo.rag`。
   - 旁白：「知识库可以用于后续任务，也可以导出迁移。」

6. **80 ~ 90 秒｜边界说明**
   - 字幕：「本地 Embedding 可用于索引；模型推理位置取决于模型服务配置。」

### 验收标准

- 回答包含三项可核对事实，并能展开来源。
- 关系图至少展示两种实体和两条有意义的关系。
- 删除资料中的某一事实后重新提问，Agent 回答「资料不足」。

## 视频 3：让稳定偏好跨会话生效

**片名**：`跨会话复用稳定工作偏好`

**时长**：60 ~ 75 秒

**演示重点**：长期约束与偏好形成可管理记忆，在新会话中按相关性取回。

### 演示前准备

准备一段同时包含长期偏好和一次性状态的对话。长期偏好为：中文输出、风险使用表格、事实附来源、禁止改写原文件；一次性状态为：「今天 16:00 前先看完临时草稿」。

### 分镜与旁白

1. **0 ~ 15 秒｜明确长期记忆范围**
   - 输入：

```text
请长期记住我的交付偏好：默认使用中文；风险项用表格；事实结论附来源；
未经确认不要修改原文件。今天 16:00 前先看完临时草稿，这条只对今天有效。
```

   - 画面：对话结束后出现记忆整理状态。
   - 旁白：「记忆整理区分长期偏好和一次性安排。」

2. **15 ~ 30 秒｜记忆管理**
   - 画面：进入记忆库，展示摘要、标签和详情；长期偏好被整理，一次性要求没有进入长期记忆。
   - 旁白：「长期记忆可以查看、检索和删除。」

3. **30 ~ 52 秒｜新会话验证复用**
   - 画面：新建会话，上传虚构风险清单并输入「整理成评审摘要」。
   - 结果：中文输出、风险表格、来源列出现，并在修改原文件前停下。
   - 旁白：「新会话根据当前任务检索相关记忆。」

4. **52 ~ 68 秒｜删除记忆**
   - 画面：搜索「禁止修改原文件」，点击删除；新会话再次测试，显示该记忆已从检索上下文中移除。
   - 旁白：「用户可以移除不再适用的长期记忆。」

5. **68 ~ 75 秒｜对比定格**
   - 字幕：「聊天记录保存会话过程；长期记忆保存可复用信息。」

### 验收标准

- 长期偏好与一次性状态的筛选结果不同。
- 第二个会话不复制第一段提示词，通过输出行为体现记忆复用。
- 删除后刷新记忆列表，确认条目消失。

## 视频 4：组合技能、工具与专业上下文

**片名**：`组合技能、工具与结构化上下文`

**时长**：80 ~ 95 秒

**演示重点**：技能定义工作方法，工具执行具体动作，结构化资源保留专业上下文，Yaklang 与 MCP 提供扩展能力。

### 演示前准备

1. 在本机启动一个只返回固定 JSON 的演示服务，例如 `http://127.0.0.1:8787/health`。
2. 准备一条已脱敏的 HTTP Flow，响应内容与演示服务一致。
3. 创建技能 `Evidence First Review`，要求先列证据再给结论，不做未授权外部请求，输出包含请求、响应、风险和建议四部分。
4. 确认 HTTP 请求工具已启用；MCP 设置页准备一个离线演示服务，但主片不依赖第三方网络。

### 分镜与旁白

1. **0 ~ 14 秒｜展示可复用能力**
   - 画面：技能库打开 `Evidence First Review`，展示流程与输出约束；切换工具库搜索 `HTTP`。
   - 旁白：「技能保存工作方法，工具执行具体动作。」

2. **14 ~ 30 秒｜挂载结构化上下文**
   - 画面：在 Agent 中 `@Evidence First Review`，再添加脱敏 HTTP Flow；资源卡片展示请求与响应。
   - 输入：

```text
使用 @Evidence First Review 分析这条 HTTP Flow；
仅允许访问 http://127.0.0.1:8787/health 复核服务状态，其他网络请求一律禁止。
```

   - 旁白：「HTTP Flow 以结构化资源进入上下文，保留原始证据和任务约束。」

3. **30 ~ 48 秒｜工具搜索与风险确认**
   - 画面：Agent 搜索并选择 HTTP 工具；调用前显示 URL、方法和风险卡片。确认目标为 `127.0.0.1` 后点击同意。
   - 旁白：「执行前展示访问目标与调用参数。」

4. **48 ~ 66 秒｜按技能要求输出**
   - 画面：结果分为请求、响应、风险、建议四部分；证据来自 HTTP Flow 与本机复核结果。
   - 旁白：「技能约束处理方法和输出结构，工具提供新的证据。」

5. **66 ~ 82 秒｜扩展能力**
   - 画面：依次展示 MCP 服务配置、Focus Mode、插件中心以及端口、风险、指纹数据库。
   - 旁白：「可以继续接入 MCP、YakScript 工具、插件和 Yaklang 安全能力。」

6. **82 ~ 95 秒｜安全收束**
   - 画面：回到审查卡片与本机地址，定格 `Authorized Demo Environment`。
   - 字幕：「专业测试应在明确授权的范围内执行。」

### 验收标准

- 主片断网后仍能完成。
- HTTP 工具只能访问 `127.0.0.1`。
- 画面不出现真实 Cookie、Token 或公网目标。
- 最终输出完整呈现技能预设的四段结构。

## 统一剪辑与静态素材

- 四支视频各自成片。
- Agent 时间线使用青绿色，知识网络使用蓝色，记忆卡片使用暖黄色。
- 静态素材包括 Agent 执行全景、知识图谱、长期记忆库、技能与工具组合、结构化 HTTP Flow 分析。
